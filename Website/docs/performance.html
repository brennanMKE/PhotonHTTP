A summary of what has been measured, with links to the records. All runs are on the owner's Apple M4 Pro (12 cores) over loopback, with the load client on the same machine and often other builds running, so treat the numbers as relative, not absolute. Each record lists its load average and method; the rules for recording are in benchmarks/README.md.

#What this means for configuration

  • Keep the default "transport": "bsd" for cleartext.
  • Leave http2.cleartext off unless you need h2c: it makes every cleartext connection sniff its first bytes.
  • Enable compression: static variants are built once, so the per-request cost is a lookup.
  • Turn on only the components you use; an unused key costs nothing, a used one costs tens of nanoseconds.
  • For proxied apps, raise pool.maxIdle to your concurrency. The proxy's known cost is the per-read timeout race (about 17 allocations and 8–10 µs per request); a kqueue-armed deadline is the planned fix.

#Tried and dropped: SIMD and Accelerate

SIMD scanning made WebSocket UTF-8 validation about 3x faster and small-frame unmasking about 2x faster, but it didn't change requests per second: the server's own code is about 0.3 µs of a roughly 22 µs request. Accelerate has nothing for byte parsing. The experiment wasn't merged; the measurements are in ../notes/simd-accelerate.md.

#Measuring yourself

swift build -c release -j 2 --product sws-bench
.build/release/sws-bench micro --filter StaticFiles       # ns and allocations per operation
scripts/guarded.sh -t 2400 -- scripts/bench-compare.sh 10 /tmp/compare.md   # vs nginx etc. (needs them installed)
scripts/guarded.sh -t 600 -- scripts/bench-proxy.sh 5 1 16 64               # proxy vs Apache and nginx

Record the load average with every result, and run on an idle machine before quoting numbers.
