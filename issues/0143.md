## Description

When a reloaded config changes restart-only keys (listeners, ports, TLS listener settings, protocols, connection limits), the server applies the rest and prints a warning that those keys were ignored. The running state then matches neither the old nor the new file. The owner wants such reloads rejected whole, and a CLI that tells the user a graceful restart is needed.

## Scope

- A reload whose config has restart-only changes is rejected whole; the running config stays. The reason (which keys) is reported.
- The server writes a small status file (default `run/status.json` next to the config, or a `statusFile` key): pid, start time, config path and SHA-256 of the loaded config, last reload time and result, and pending restart-only keys. Write it atomically.
- CLI subcommands on the `SwiftWebServer` executable:
  - `check [--config PATH]`: validates a config and, if a server is running (status file, live pid), shows what would change and whether it can hot-reload or needs `restart`.
  - `reload`: does `check`, sends SIGHUP to the running pid, waits for the status file to report the result, prints it, and exits non-zero on failure or rejection.
  - `status`: prints the status file in readable form.
  - When a restart is required, the message names the keys and says to run `SwiftWebServer restart` (#0144).
- No new listening socket for control (signals plus the status file only), so nothing new is reachable over the network.

## Acceptance criteria

- Tests for rejection and the status file. CLI tests run the binary through `scripts/guarded.sh` on loopback with port 0.
- docs/guide/running-on-a-mac.md documents the commands.

## Root cause

`ServerMain.reload` built and swapped in the new chain first and only then compared
restart-only keys, printing `…; needs a restart, ignored`: the running state mixed the new
file's reloadable keys with the old file's listener keys. Nothing recorded the server's state
outside stderr, so no tool could tell what was running or what a reload would do.

## Fix

- **Rejection.** The reload compares `restartOnlyChanges(comparedTo: startup)` before building
  anything; when it is not empty nothing applies (not the chain, not the identity), stderr says
  `reload rejected, keeping the running configuration: maxConnections changed and needs a
  restart; run `SwiftWebServer restart` to apply them`, and the status file records it. The
  access log is still reopened (rotation).
- **Status file** (`ServerStatus`, ConfigFile): JSON, written atomically (temporary file, rename)
  with mode 0600 by `StatusRecorder` (executable) once the listeners are bound, after each
  reload and at a clean exit (`state: stopped`). `pid`, `started`, `config`, `configSHA256`
  (`ConfigFile.contentSHA256`, CommonCrypto), `arguments`, `listening`, `settings` (per-key
  16-hex digests of `ServerSettings.comparisonValues`, so no values or secrets), `reloads`,
  `lastReload` (`time`, `trigger`, `result` reloaded/failed/rejected, `message`, `changed`,
  `restartRequired`), `restartRequired`. New key `statusFile` (default `run/status.json`,
  resolved against the config file's directory; `false`/`null` off); written only with a
  config file.
- **CLI** (`ControlCommand`, `Sources/SwiftWebServer/ControlCommands.swift`), dispatched when
  the first argument is a command:
  - `check`: loads, validates and builds the config like a reload (TLS identity in memory
    only); with a live server for that config (status file, `kill(pid, 0)`), diffs digests
    (`ServerSettings.changes(from:to:)`) and prints `can hot-reload: …`, `no setting changes`,
    or `needs a restart: …` (exit 3). Uses the running server's command-line overrides
    unless given its own.
  - `reload`: `check`, then SIGHUP and wait for `reloads` to grow in the status file; exit 0 /
    1 (failed, timeout) / 3 (rejected). Does not signal for an invalid or restart-needing config.
  - `status`: readable summary, `--json` for the file; exit 0 only while running.
  - `restart`: seam for #0144 (`ControlCommand.restartCommand`, `restartMessage`); prints how
    to restart by hand and exits 1.
- No control socket: signals and the status file only.

## Gotchas

- `--root` moves `baseDirectory` to the working directory, so the status file must resolve
  against the config file's directory, not `baseDirectory`; the first full run left a
  `run/status.json` in the repo root before that was fixed.
- Comparing across processes needs value texts that do not depend on hashing seeds:
  `mimeTypes` and `errorPages` file maps are sorted before digesting.
- With the watcher on (#0142), a file with restart-only changes is rejected on every poll-
  detected change until it is reverted or the server restarts; `restartRequired` stays set.
