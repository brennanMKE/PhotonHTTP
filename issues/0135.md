## Description

Found while writing `docs/guide/http3.md`. Since #0127, the executable wraps its handler chain in `ReloadableHandler` (`Sources/SwiftWebServer/ServerMain.swift`). HTTP/2 and HTTP/3 decide whether to send `SETTINGS_ENABLE_CONNECT_PROTOCOL` with `MiddlewareChainInspector.extendedConnectProtocols(in: handler)`. That walk stops at `ReloadableHandler`, which is neither a `MiddlewareChainContainer` nor an `ExtendedConnectProvider`, so it never finds the `ReverseProxy` with a `websocket` mount. Clients then can't open WebSockets over h2 (RFC 8441) or h3 (RFC 9220) through the shipped binary. HTTP/1.1 Upgrade is unaffected.

## Acceptance criteria

- `extendedConnectProtocols(in:)` on a `ReloadableHandler` returns the protocols of its current chain, and a reload that adds or removes a WebSocket mount is reflected for new connections.
- `ReloadableHandler` doesn't become a `MiddlewareChainContainer`, because that would make the server also find (and run twice) the inner chain's `ServerComponent`s and observers.

## Root cause

#0127 wrapped the executable's chain in `ReloadableHandler`, which conforms to `ServerComponent` and `ConnectionObserver` but not to `ExtendedConnectProvider` or `MiddlewareChainContainer`. `MiddlewareChainInspector.extendedConnectProtocols(in:)` stopped at the wrapper and returned nothing, so HTTP/2 and HTTP/3 never set `SETTINGS_ENABLE_CONNECT_PROTOCOL`.

## Fix

`ReloadableHandler` conforms to `ExtendedConnectProvider` and returns the protocols of its current chain. HTTP/2 and HTTP/3 check per connection, so a reload that adds or removes a WebSocket mount is seen by new connections. The wrapper stays out of `MiddlewareChainContainer` so the inner chain's components and observers aren't found (and run) twice.

## Verification

- New `ReloadableHandlerTests.extendedConnectProtocolsFollowTheCurrentChain`: the wrapper reports `["websocket"]`, a reload to a chain without one reports none, and the wrapper is still the only component and observer.
- Full suite: 1,638 tests, no failures (the 4 known intermittent QUIC close-code issues aside).
- Not verified end to end with a real h2/h3 WebSocket client through the shipped binary.
