## Description

Found while writing docs/guide/tls.md. When `sec_identity_create` fails, `makeOptions` and `QUICListener.init` throw `TransportError.failed(code: -1)`. `describe()` in `ServerMain.swift` only explains codes above 0, so startup prints `cannot serve on …: failed(code: -1)`. Separately, `TLSVersion.protocolVersion` silently turns versions below TLS 1.2 into 1.2.

## Acceptance criteria

- Identity failures throw a specific error (for example `TLSIdentityError` or a new `TransportError` case) whose description says what failed and what to check (file, password, missing private key, unsupported key type).
- An unsupported minimum TLS version is rejected with a clear error (or documented as clamped and warned about at startup), not silently changed.
- Tests for the error descriptions; no keychain access.

## Relation

- **Milestone:** M17 follow-ups
- **Blocked by:** none

## Root cause

`sec_identity_create` ran only when a listener was created (`TLSConfiguration.makeOptions`,
`QUICListener.init`), so its failure could only be reported as the generic
`TransportError.failed(code: -1)`, which `ServerMain.describe` prints raw. Import-time errors
were described by a switch in `ServerMain` that knew only three cases. `TLSVersion.protocolVersion`
fell back to `.TLSv12` for any value Security.framework does not name, and passed TLS 1.0/1.1
through, so a bad minimum was silently changed.

## Fix

- `TLSIdentity.init(pkcs12:password:)` now also reads the certificate's public key type
  (`SecCertificateCopyKey` + `SecKeyCopyAttributes`; no private-key operation, no keychain)
  and creates the `sec_identity_t` once. New `TLSIdentityError` cases `unsupportedKeyType` and
  `notUsableForTLS`; the enum is `CustomStringConvertible` with a "what failed; what to check"
  message per case (wrong password and MAC failure, missing passphrase, not PKCS#12 / OpenSSL 3
  encryption, no private key, key type, mismatched key). `ServerMain.describe(identity:)` is gone.
- Listeners use the prebuilt identity, so they no longer throw `failed(code: -1)`.
- New `TLSConfigurationError` (`unsupportedMinimumVersion`, `unsupportedMaximumVersion`,
  `emptyVersionRange`) with descriptions; `TLSConfiguration.validate()` checks the range and
  `TCPListener.init` and `TCPTransport.connect` (client options) throw it. Only TLS 1.2 and 1.3
  are accepted; nothing is clamped.

## Gotchas

- `TLSVersion(rawValue: 0x0301)` prints as `TLS(0x301)`; the error message names it that way.
- The key type comes from the certificate's public key on purpose: reading attributes of the
  private key is not needed and keeps clear of anything keychain-shaped.
