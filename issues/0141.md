# 0141 — TLS identity failures are reported as failed(code: -1)

| | |
|---|---|
| **Status** | open |
| **Module** | NetworkTransport / SwiftWebServer |
| **Platform** | macOS |
| **First seen** | 2026-11-13 |

## Description

Found while writing docs/guide/tls.md. When `sec_identity_create` fails, `makeOptions` and `QUICListener.init` throw `TransportError.failed(code: -1)`. `describe()` in `ServerMain.swift` only explains codes above 0, so startup prints `cannot serve on …: failed(code: -1)`. Separately, `TLSVersion.protocolVersion` silently turns versions below TLS 1.2 into 1.2.

## Acceptance criteria

- Identity failures throw a specific error (for example `TLSIdentityError` or a new `TransportError` case) whose description says what failed and what to check (file, password, missing private key, unsupported key type).
- An unsupported minimum TLS version is rejected with a clear error (or documented as clamped and warned about at startup), not silently changed.
- Tests for the error descriptions; no keychain access.
