# 0133 — No release tags, so other packages can only depend on branch main

| | |
|---|---|
| **Status** | open |
| **Module** | Package / Docs |
| **Platform** | macOS |
| **First seen** | 2026-11-12 |

## Description

The repository has no git tags. A third-party package or custom server can only write `.package(url: "https://github.com/brennanMKE/SwiftWebServer.git", branch: "main")`, which:
- breaks without warning whenever a public API changes,
- can't be resolved by version, and
- can't be depended on from a package that itself uses version requirements.

Nothing marks which declarations are public API and which are public only so targets can see each other.

## Scope

- Decide the public API surface for each library product, starting with HTTPCore's `HTTPHandler`, `HTTPMiddleware` and message types, `HTTPServer.Server` and its builder, and each component's initializer. Mark or move the declarations that are public only for cross-target use, using `package` access where possible.
- Add a CHANGELOG and tag `0.1.0`. 0.x semver applies: a minor version may break source compatibility.
- Update `Examples/custom-server` and the guides to use `from: "0.1.0"`.
- Optionally add an API check (`swift package diagnose-api-breaking-changes`) to the verification steps.

## Acceptance criteria

- `git tag` shows `0.1.0`. An outside package resolves SwiftWebServer by version and builds `Examples/custom-server`'s code.
- The docs say which products are stable.
