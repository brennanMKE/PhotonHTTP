## Description

The owner wants hot reload with no manual step. Today a reload happens only on SIGHUP (#0127). Requests already use the swapped-in, in-memory chain; no request reads or checks the config.

## Scope

- An out-of-band watcher, a child task of the server's task group (no unstructured `Task {}`, no DispatchQueue: poll `stat` (mtime, size, inode) every N seconds, default 2 s, configurable with a `reload` key such as `{"watch": true, "interval": 2}`). It watches `http-config.json` and the files the config names that a reload reads (TLS identity after #0140, error pages, auth files if any).
- On a change: debounce (wait for the file to stop changing, so a half-written file isn't loaded), then run the same path as SIGHUP. SIGHUP stays as a manual trigger.
- A change made with an atomic rename (editors, `tailscale cert`, lego) is detected through the inode.
- Per-request cost: measure `ReloadableHandler`'s per-request generation lookup (about 8 ns since #0127) and reduce it to an atomic load of the current generation if that keeps the per-connection observer behaviour correct. Benchmark before and after with `sws-bench`.

## Acceptance criteria

- Editing the config (or replacing it by rename) reloads it within the interval with no signal. A malformed or half-written file never replaces the running config.
- Tests use a temporary directory and an injectable clock/interval; no fixed ports.

## Root cause

Reloads came only from SIGHUP (#0127), run synchronously on the signal queue; nothing watched
the config or the files it names. The per-request generation lookup read the connection's
generation from the context and followed its successor links.

## Fix

- `ConfigReloader` (ConfigFile, new `ConfigReloader.swift`), a `ServerComponent` passed to
  `Server(components:)`: one task runs reloads one at a time from an `AsyncStream` of
  triggers (low-rate signal, `bufferingNewest(4)`); a child task polls `stat` (device, inode,
  size, mtime: `FileFingerprint`) of the plan's paths every `interval`, waits until two polls
  `settle` apart agree (default `min(interval, 0.5 s)`), then yields `.watch(changed:)`.
  SIGHUP calls `requestReload()` (`.signal`). A reload records the files as it reads them,
  so the watcher reports only later changes; the plan returned by the reload (the files the
  running configuration names) is watched from then on. Nothing reloads once the server
  drains. Clock and settle are injectable.
- `ServerSettings.reload` (`"reload": {"watch": true, "interval": 2}`, or `true`/`false`),
  `ServerSettings.reloadInputs` (TLS identity, `auth[].basic.file`, error page files under
  `root` and every `hosts[].root`) and `watchPlan(configPath:)`.
- `ServerMain`: the reload returns the settings now running (or `nil`), the watcher plan
  follows them; `configPath(_:environment:)` factored out; message
  `PATH changed, reloading the configuration`.
- `ReloadableHandler`: requests on a connection that holds a generation do a context check
  (`contains`, no retain) and one unretained acquiring atomic load of the current generation
  (`ReloadCurrentGeneration.loadUnretained()`). Safe because the connection's generation is
  alive (its context holds it) and links strongly to every newer generation; the current one
  is never older than the connection's. The successor atomic and `latest()` walk are gone;
  the strong links remain. Requests without connection state keep the lock. Connection
  observers, components, #0135 extended CONNECT and #0139 protocol response observers are
  unchanged (merged with main after the code commit).

## Gotchas

- The lookup was not where the reloadable overhead goes: the locked path (no context) was
  already as fast as the context path, and with the lookup gone dispatch reloadable is still
  about 10 ns over `empty`. The rest is the unspecialized call through `any HTTPHandler` into
  a generic class (`Generation<Handler>` field access, a retain); copying the handler out
  under `_withUnsafeGuaranteedRef` measured the same. A further cut would need a
  non-generic request path, not a cheaper lookup.
- The watcher is on by default, so tests that edit the config and then send SIGHUP must set
  `"reload": false`, or a poll landing between the write and the signal adds a second reload.
- `@inlinable` code that touches `Atomic` needs `public import Synchronization`.
