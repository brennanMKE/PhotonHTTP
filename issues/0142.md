# 0142 — Config changes need a manual SIGHUP; the server should watch its files and hot-reload

| | |
|---|---|
| **Status** | open |
| **Module** | SwiftWebServer / ConfigFile |
| **Platform** | macOS |
| **First seen** | 2026-11-13 |

## Description

The owner wants hot reload with no manual step. Today a reload happens only on SIGHUP (#0127). Requests already use the swapped-in, in-memory chain; no request reads or checks the config.

## Scope

- An out-of-band watcher, a child task of the server's task group (no unstructured `Task {}`, no DispatchQueue: poll `stat` (mtime, size, inode) every N seconds, default 2 s, configurable with a `reload` key such as `{"watch": true, "interval": 2}`). It watches `http-config.json` and the files the config names that a reload reads (TLS identity after #0140, error pages, auth files if any).
- On a change: debounce (wait for the file to stop changing, so a half-written file isn't loaded), then run the same path as SIGHUP. SIGHUP stays as a manual trigger.
- A change made with an atomic rename (editors, `tailscale cert`, lego) is detected through the inode.
- Per-request cost: measure `ReloadableHandler`'s per-request generation lookup (about 8 ns since #0127) and reduce it to an atomic load of the current generation if that keeps the per-connection observer behaviour correct. Benchmark before and after with `sws-bench`.

## Acceptance criteria

- Editing the config (or replacing it by rename) reloads it within the interval with no signal. A malformed or half-written file never replaces the running config.
- Tests use a temporary directory and an injectable clock/interval; no fixed ports.
